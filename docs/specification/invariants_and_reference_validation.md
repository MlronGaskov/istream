# Инварианты и процедура эталонной проверки

Пусть состояние клиента $C_Q=\{f_1,f_2,\ldots,f_s\}$, где каждый материализованный фрагмент имеет вид $f_i=(I_i,M_i,w_i)$, а $F_i=R(Q,I_i,w_i)$ - эталонный результат диапазона для той же версии.

Критерий корректности фрагмента:

$$
Correct(f_i)\iff M_i=F_i.
$$

Равенство означает совпадение записей по идентификаторам, ключам порядка, значениям пользовательской проекции и порядку следования.

Для последовательности записей $X$ обозначим:

$$
Ids(X)=\{id(m)\mid m\in X\}.
$$

## Локальные инварианты

### 1. Уникальность `rowId`

Количество различных идентификаторов внутри каждого фрагмента должно совпадать с количеством хранимых записей:

```math
\left|\{id(m)\mid m\in M_i\}\right|=|M_i|.
```

### 2. Принадлежность диапазону

Ключ порядка каждой записи фрагмента принадлежит его диапазону:

$$
\forall m\in M_i:\ key(m)\in I_i.
$$

### 3. Корректный порядок

Пусть $M_i=\langle m_1,m_2,\ldots,m_n\rangle$. Ключ каждой следующей записи больше ключа предыдущей согласно порядку $\prec_Q$:

$$
\forall j\in\{1,\ldots,n-1\}:
key(m_j)\prec_Q key(m_{j+1}).
$$

### 4. Полнота диапазона

Набор идентификаторов клиентского фрагмента совпадает с эталонным результатом диапазона:

$$
Ids(M_i)=Ids(F_i).
$$

### 5. Корректность значений

Для каждой материализованной записи существует запись эталонного результата с тем же идентификатором, ключом порядка и пользовательским значением:

$$
\forall m\in M_i\ \exists m'\in F_i:
$$

$$
id(m)=id(m')
\land key(m)=key(m')
\land value(m)=value(m').
$$

## Инварианты состояния клиента

### 6. Непересечение материализованных диапазонов

Диапазоны различных фрагментов не пересекаются:

$$
\forall i\ne j:\ I_i\cap I_j=\varnothing.
$$

В общем случае фрагменты могут иметь разные watermark $w_i$, поэтому глобальная уникальность `rowId` не требуется.

## Нормализация состояния

Операция $Normalize(C_Q,V)$ приводит все проверяемые фрагменты к общей версии $V$.

Для каждого фрагмента $f_i=(I_i,M_i,w_i)$, где $w_i\le V$:

1. Если $w_i=V$, актуализация не требуется.
2. Если replay доступен, применить все релевантные изменения с версиями из интервала $(w_i,V]$.
3. Если replay недоступен, повторно получить результат диапазона $I_i$ из состояния $D_V$.
4. При replay дождаться префикса потока с watermark не меньше $V$ и убедиться, что все релевантные изменения с версиями не больше $V$ применены. Изменения с версиями больше $V$ в нормализованное состояние не включаются. Подтверждение требуется и при отсутствии событий в диапазоне.
5. После завершения актуализации установить watermark фрагмента $V$.

Результат нормализации:

$$
C_Q^V=Normalize(C_Q,V)
=\{(I_i,M_i^V,V)\}_{i=1}^{s}.
$$

Все фрагменты $C_Q^V$ имеют общую версию $V$. Их корректность проверяется отдельно сравнением с эталоном.

## Глобальный инвариант после нормализации

### 7. Глобальная уникальность `rowId`

После приведения всех проверяемых фрагментов к версии $V$ количество различных идентификаторов во всём состоянии клиента должно совпадать с общим количеством хранимых записей:

```math
\left|\{id(m)\mid\exists i:\ m\in M_i^V\}\right|
=
\sum_{i=1}^{s}|M_i^V|.
```

## Процедура эталонной проверки

Проверка выполняется через barrier для выбранной версии $V$.

1. Остановить генератор изменений.
2. Дождаться завершения всех начатых атомарных групп изменений и зафиксировать текущую серверную версию $V$.
3. Выполнить $Normalize(C_Q,V)$: для каждого проверяемого фрагмента применить доступный replay либо повторно получить результат диапазона из $D_V$.
4. Убедиться, что нормализация завершена: при replay достигнут watermark не меньше $V$ и применены все релевантные изменения до $V$, в том числе при отсутствии событий в диапазоне.
5. Для каждого материализованного диапазона $I_i$ вычислить эталонный результат из состояния $D_V$: $F_i=R(Q,I_i,V)$.
6. Для каждого фрагмента проверить:
   - уникальность идентификаторов внутри фрагмента;
   - принадлежность ключей $key(m)$ диапазону $I_i$;
   - совпадение набора идентификаторов с $F_i$;
   - совпадение ключей $key(m)$ и значений $value(m)$ с $F_i$;
   - корректный порядок записей.
7. Для всего нормализованного состояния $C_Q^V$ проверить глобальную уникальность идентификаторов и непересечение материализованных диапазонов.

Клиентское состояние на версии $V$ считается корректным, если все проверки выполнены успешно.
